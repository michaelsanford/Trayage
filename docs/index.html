Features

Trayage is meant to stay out of your way until something needs you. Here is what that looks like day to day.

Notifications you will actually want

When a review request, mention or assignment comes in, Trayage shows an ordinary Windows notification. You hear about it without a browser tab open, and clicking it opens the pull request.

Each notification says what happened, which item it was about and which repository it is in, so you can tell at a glance whether it can wait. Notifications use the Windows App Runtime. If it is missing, the inbox still works and Settings links to the download.

You decide what is worth an interruption

Each kind of activity has its own switch. Plenty of people keep review requests and mentions on and leave CI results off, but that is up to you.

You can also choose a sound and its volume, or skip the pop-up and only play the sound.

All your accounts in one inbox

Connect a work and a personal GitHub account, a couple of Bitbucket workspaces and your GitLab account, and they all feed the same list. Give each one a name so you can tell their items apart.

Need a quiet week on one of them? Pause it. Trayage keeps the sign-in, so turning it back on is one click.

And the rest

Group it your way

Group the inbox by repository or by owner, or turn grouping off and read it newest first under Today and Yesterday.

Watched repositories

Add a repository to your watch list to see everything that happens in it, including pull requests you are not part of.

Mark as read

Clear a single item, a whole group or the entire inbox. Read items stay dimmed in the list, or you can hide them.

Encrypted tokens

OAuth tokens are encrypted with Windows DPAPI, so only your Windows account on this PC can read them. They are never stored in plain text.

No flood on first run

The first check after you connect an account takes note of what is already there instead of sending you a notification for every item.

Starts with Windows

Turn on Start with Windows and Trayage is in the tray as soon as you sign in. Light, dark and system themes are included.

Supported services

Each service signs in the way it recommends for desktop apps. To add a second account on the same service, click Connect again.

GitHub

Sign-in: OAuth device flow

Reads your GitHub notifications through the GitHub API.

  • Review requests, mentions and assignments
  • CI and check status changes
  • Activity on watched repositories

Bitbucket Cloud

Sign-in: OAuth authorization code with a local redirect

Bitbucket Cloud has no notifications API, so Trayage builds the inbox from pull request queries.

  • Pull requests you opened
  • Review requests in watched repositories
  • All activity in watched repositories
  • Watched repositories are set per account

GitLab

Sign-in: OAuth device flow

Reads your GitLab to-do list through the GitLab API, so there is nothing to set up per repository.

  • Assignments, mentions and review requests
  • Failed pipelines

Bitbucket mentions and CI status are not shown in this version, because Bitbucket Cloud has no feed for them. Bitbucket review requests are only found in watched repositories. The README lists the details.

How it works

  1. At the interval you set, Trayage asks each connected account for its activity and follows any rate limit the service reports.
  2. Results from all services are converted into one item format, and duplicates are removed.
  3. The new list is compared with the previous one to find items that are new or have changed.
  4. Your notification settings decide which of those items show a Windows notification, by kind of activity or by watched repository.

Verifying a release

Each release includes a GitHub build provenance attestation, a Sigstore cosign signature and a CycloneDX SBOM. Verify-Release.ps1 in the repository checks all three.

Windows PowerShell
PS C:\Downloads> .\Verify-Release.ps1
# 1/3  GitHub Attestation
  [PASS] trayage-v1.0.0-win-x64.zip
  [PASS] trayage-v1.0.0-win-arm64.zip
# 2/3  Cosign Keyless Signature
  [PASS] trayage-v1.0.0-win-x64.zip
  [PASS] trayage-v1.0.0-win-arm64.zip
# 3/3  SBOM Integrity (CycloneDX)
  [PASS] 84 dependency components listed

  Release v1.0.0 passed all verification checks.

Build provenance

Shows which workflow, commit and runner built each archive.

gh attestation verify

Signature

A Sigstore keyless signature issued through GitHub OIDC, so there is no long-lived signing key.

cosign verify-blob

Software bill of materials

A CycloneDX SBOM listing every dependency is attached to each release.

trayage-<tag>-sbom.cdx.json

Running the checks by hand

# 1. GitHub build provenance
gh attestation verify trayage-v1.0.0-win-x64.zip --repo michaelsanford/Trayage

# 2. cosign keyless signature (the identity is the release workflow at that tag)
cosign verify-blob `
  --bundle trayage-v1.0.0-win-x64.zip.bundle `
  --certificate-identity "https://github.com/michaelsanford/Trayage/.github/workflows/release.yml@refs/tags/v1.0.0" `
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" `
  trayage-v1.0.0-win-x64.zip

Project structure

Trayage.AppThe WPF and WPF-UI application: tray icon, inbox flyout, Settings window, notifications, and the dependency injection setup.
Trayage.CoreService providers, inbox merging and comparison, the polling service, notification rules, settings, and the DPAPI token store.
Trayage.Core.TestsxUnit tests for merging, comparison, notification rules, settings, the token store, and each provider's mapping.

Built with .NET 11, WPF, WPF-UI, Octokit, CommunityToolkit.Mvvm and the Windows App SDK.
